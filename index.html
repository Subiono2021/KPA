Bagaimana Proyeksi "Menghapus" Galat?

Bayangkan proyeksi sebagai bayangan sinar: arah sinar adalah arah kernel, bidang lantai adalah Im(P). Objek yang bergeser sejajar sinar (δ ∈ ker) tidak mengubah bayangannya.

▲ Objek bergeser sejajar arah kernel → bayangan Px tetap tak berubah

🎯
Bayangan Tetap

Px identik untuk x dan x+δ

↗️
Arah "Tak Terlihat"

δ ∈ ker(P) — sejajar sinar

✨
Invarian Eksak

P(x+δ) = Px — bukan aproksimasi

13.1 · Pendahuluan

Proyeksi & Kernel: Intuisi Dasar

Definisi Proyeksi:
$P^2 = P$
Idempoten: menerapkan proyeksi dua kali sama dengan sekali.
Kernel:
$\ker(P) = \{x \mid Px = 0\}$
Elemen di kernel "tak terlihat" oleh proyeksi.
Konsekuensi Kunci:
$P(x + \delta) = Px \quad \forall \delta \in \ker(P)$
Galat di kernel tidak memengaruhi hasil.
Batas: Mekanisme ini selektif hanya $\delta \in \ker(P)$ yang dieliminasi, bukan sembarang galat.
💡 Poin penting: Proyeksi bukan pengganti ECC/QEC umum ia menyediakan mekanisme aljabar untuk kelas galat tertentu yang memenuhi kondisi kernel.
13.2.1 · Landasan Teori

Lapangan Galois $\mathbb{F}_{2^8}$

Konstruksi

$\mathbb{F}_{2^8} \cong \mathbb{F}_2[x]/(f(x))$
dengan polinomial ireduksibel standar AES:
$f(x) = x^8 + x^4 + x^3 + x + 1$
  • $2^8 = 256$ elemen (byte)
  • Karakteristik 2: $a + a = 0$
  • Penjumlahan ≙ XOR

Mengapa $\mathbb{F}_{2^8}$?

1. Representasi byte

Setiap elemen $\in \{0,\ldots,255\}$.

2. Operasi diskrit langsung

Matriks dan vektor bekerja langsung pada data byte.

3. Kompatibel dengan AES

Modulus sama dengan konstruksi aljabar AES.

⚠ Karakteristik 2 bukan penyebab penghapusan galat itu hanya struktur operasi. Penghapusan galat berasal dari $P_{\mathrm{prv}}\delta = 0$.
13.2.3–13.2.4

Proyeksi Rank-1 & Struktur Kernel

$P = uv^T, \quad u \in \mathbb{F}_{2^8}^{k}, \; v \in \mathbb{F}_{2^8}^{k}$

Kapan Idempoten?

$P^2 = (v^T u)\, P$
$P^2 = P \iff v^T u = 1$

Image & Kernel

$\operatorname{Im}(P) = \operatorname{span}\{u\}$
$\ker(P) = \ker(v^T)$
$\dim\ker(P) = k - 1$
Catatan penting: Implementasi SageMath tidak memaksakan $v^T u = 1$. Jadi $P_{\mathrm{pub}}$ secara umum adalah operator rank-1, bukan proyeksi idempoten. Sifat kernel tetap berlaku karena hanya bergantung pada $P_{\mathrm{prv}}\delta = 0$.

13.2.6

Penghapusan Galat Selektif

Misalkan vektor $c$ dikirim dan mengalami gangguan $\delta$, sehingga diterima $c' = c + \delta$.

$P_{\mathrm{prv}}\delta = 0 \;\Longrightarrow\; P_{\mathrm{prv}}c' = P_{\mathrm{prv}}(c+\delta) = P_{\mathrm{prv}}c$

✓ Berhasil (δ ∈ kernel)

Komponen gangguan hilang dari hasil proyeksi. Berlaku eksak.

✗ Tidak (δ ∉ kernel)

Secara umum $P_{\mathrm{prv}}(c+\delta) \neq P_{\mathrm{prv}}c$. Hasil dapat terganggu.

Yang menentukan: bukan besarnya $\delta$, melainkan apakah $\delta$ berada dalam kernel. Ini membedakan penghapusan galat selektif dari skema koreksi galat umum.
13.2.8

Operator $Q = I + P$ pada Karakteristik 2

Ekspansi

$(I+P)^2 = I + P^2$
karena $P + P = 0$ di karakteristik 2.

Kapan Involusi?

$Q^2 = I \iff P^2 = 0$
Involusi bukan untuk sembarang proyeksi idempoten.

Jika $P^2 = P \neq 0$

$Q^2 = I + P \neq I$

Implikasi

Sifat kernel dan penghapusan galat tidak bergantung pada $Q$ sebagai involusi. $Q$ hanya didefinisikan dari $P$.

📌 Penting: klaim bahwa $Q$ adalah involusi harus dibuktikan dari $P^2 = 0$, bukan diasumsikan. Operator dengan $P^2 = 0$ disebut nilpoten.
13.2.9

Pemisahan Lapisan Aljabar & Kriptografi

📐
Lapisan Aljabar Proyeksi, kernel, penghapusan galat selektif untuk $\delta \in \ker(P_{\mathrm{prv}})$
🔐
Lapisan Kriptografi AES-256-GCM (kerahasiaan + integritas), HKDF-SHA256 (derivasi), X25519 (pertukaran kunci)
Data → Proyeksi → Penghapusan Galat Selektif  ‖  Material Kunci → AES-256-GCM → Kerahasiaan + Integritas
⚠ Proyeksi linear tidak memberi kerahasiaan. Setiap klaim keamanan harus dikaitkan dengan primitive kriptografi, bukan pada sifat kernel.
13.3.1

Penurunan Parameter Protokol

Password → scrypt(N=2¹⁴, r=8, p=1) → ikm
ikm → HKDF(info="alice-seed"/"bob-seed") → 2 kunci X25519 → shared secret s
s → HKDF(salt="Algebra-Params", info="algebra-seed") → 64 byte → (u, v, Pprv)
s → HKDF(salt="GCM-Salt", info="AES-256-Key") → kunci AES-256
🔑

Pemisahan Material

Kompromi satu material tidak otomatis mengungkap yang lain. Setiap fungsi punya info HKDF berbeda.

🎯

Opsi Low-Rank

$P_{\mathrm{prv}} = AB$ dengan $r < k$ (low-rank) → kernel dijamin $\neq \{0\}$ → sifat penghapusan galat dapat didemonstrasikan.

Catatan: Simulasi X25519 dilakukan deterministik dari password untuk reproduktibilitas. Protokol nyata: kunci independen, pertukaran publik via saluran terbuka.
13.3.2

Enkripsi (Alice)

Untuk setiap blok plaintext $\mathbf{m}_i$:

1. S-Box

$\mathbf{m}_i' = S(\mathbf{m}_i)$
S-Box mencegah serangan interpolasi langsung.

2. Vektor Acak

$\mathbf{e}_i \leftarrow \text{CSPRNG}$
CSPRNG membuat skema probabilistik.

3. Ciphertext Aljabar

$\mathbf{c}_i = P_{\mathrm{pub}}\mathbf{m}_i' + Q\mathbf{e}_i$

4. Residual

$\mathbf{k}_i = \mathbf{m}_i' + P_{\mathrm{prv}}\mathbf{c}_i$
Payload = $\mathbf{c} \Vert \mathbf{k}$ → dienkripsi & diautentikasi dengan AES-256-GCM (nonce acak 96-bit + AAD konteks).
13.3.3

Dekripsi (Bob)

  1. Derivasi material kunci yang sama melalui X25519 + HKDF.
  2. Bangkitkan kembali $P_{\mathrm{pub}}, Q, P_{\mathrm{prv}}$.
  3. Authenticated decryption AES-GCM. Jika gagal → tolak.
  4. Ekstrak $\mathbf{c}$ dan $\mathbf{k}$ dari payload.
  5. Rekonstruksi:
    $\mathbf{m}_i' = \mathbf{k}_i + P_{\mathrm{prv}}\mathbf{c}_i$
  6. Inverse S-Box: $\mathbf{m}_i = S^{-1}(\mathbf{m}_i')$.
  7. Gabung byte, hapus padding, decode UTF-8.
Bukti kebenaran: $\mathbf{k}_i + P_{\mathrm{prv}}\mathbf{c}_i = (\mathbf{m}_i' + P_{\mathrm{prv}}\mathbf{c}_i) + P_{\mathrm{prv}}\mathbf{c}_i = \mathbf{m}_i'$ karena karakteristik 2 ($P_{\mathrm{prv}}\mathbf{c}_i + P_{\mathrm{prv}}\mathbf{c}_i = 0$).
13.2.9 · 13.3.1–13.3.3

Protokol Lengkap: Dua Lapisan Terpisah

🔐 Lapisan Kriptografi (kiri)

Menjamin kerahasiaan & integritas via AES-256-GCM, HKDF-SHA256, X25519. Tidak menyentuh isi aljabar hanya membungkusnya.

📐 Lapisan Aljabar (kanan)

Menyediakan penghapusan galat selektif untuk \(\delta \in \ker(P_{\mathrm{prv}})\). Tidak memberi kerahasiaan hanya transformasi linear.

⚠ Pemisahan tegas (13.2.9): Data mengalir dari aljabar → kriptografi, bukan sebaliknya. Kompromi satu lapisan tidak otomatis membocorkan lapisan lain inilah inti domain separation HKDF.

Rangkuman Bab 13 & Catatan Teknis Deck

📐 Inti Matematis

Untuk \(P=uv^T\) atas \(\mathbb{F}_{2^8}\):

\(P^2=(v^Tu)P,\quad \ker(P)=\ker(v^T)\)

Jika \(\delta\in\ker(P)\), maka \(P(x+\delta)=Px\) — eksak, bukan aproksimasi.

🔐 Inti Kriptografis

Kerahasiaan & integritas hanya dari AES-256-GCM + HKDF-SHA256 + X25519.

Lapisan aljabar tidak memberi kerahasiaan: \(P_{\text{prv}}\) dapat dipulihkan via sistem linear \(\mathcal{O}(k^3)\) dalam model KPA.
